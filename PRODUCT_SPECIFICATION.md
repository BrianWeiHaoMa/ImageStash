# ImageStash — Product Specification

## Authority

This document outranks every other document, decision, and line of code in this project. `TECHNICAL_SPECIFICATION.md` is written from it and ranks second. `Fixed decisions` and `Non-goals` hold everywhere. `Guarantees` hold for every use inside `Operating envelope` and bind exactly as strongly there; outside the envelope nothing is promised. Unassigned implementation choices are deliberately open for downstream work at its own level. An explicitly pending decision remains with its named owner and is not a delegated choice. Work that finds a line here unworkable stops the dependent work and reports the conflict and a proposed amendment; independent work continues. It does not work around the line, narrow it, or change the envelope to make a failure disappear. Labels (`E1`, `F1`, `G1`, `N1`, `L1`) are permanent and are how every downstream document cites this one.

## Product

ImageStash is a Windows 11 tray application that keeps one person's reaction images and GIFs one shortcut away from any chat. Its user is one person running it on their own Windows PC: the author, and anyone else who obtains a build. Each user keeps their own stash on their own PC; nothing is shared between people or between Windows accounts. It is built for Windows only, with the parts that touch Windows kept apart (F13), so that a later Linux or macOS build is an addition rather than a rewrite.

They get a **stash**: a collection filled by dropping files in, pasting a copied image, screenshotting a region of the screen, or recording a few seconds of it; found again by thumbnail, tag, name, favorite or recent use; captioned, cropped, trimmed, blurred or annotated as **layers** over an untouched **original**; and handed into the message box they were typing in with one Enter. The paste moment is the product: shortcut, glance or type two letters, Enter, and the picture is in the composer, with the message never sent by ImageStash. Everything else exists to make that moment better and stays out of its way.

What must not be lost: every saved item, with its original, its **finished picture** (the rendered result of its layers, which the grid shows (G6) and every handoff uses), its name, tags, favorite flag, use history and layers, survives restarts, crashes, process kills and a newer build (G28, G31). The accepted limits: the one change in flight when the process dies may be lost, and is then absent rather than half done (G28); an edit discarded past its Undo window is gone, and the live layers are the only history of edits (G25); power loss, disk failure, and anything that changes the stash folder behind ImageStash's back are outside the promise (E2, E3); how a destination app displays what it receives is that app's business (E6); the build is an unsigned self-contained folder the user copies onto the PC, with no installer, updater or second language (N8), so Windows warns before the first run of a downloaded copy, and a PC with Smart App Control on is outside the promise (E1); a stash folder is used from one PC at a time (E2).

## In use

ImageStash starts with Windows and lives in the tray. While typing in a chat, the user presses `Ctrl+Alt+Space` (F5). The **stash window** opens as a **flyout** beside the text caret, the search box focused with its text selected, showing what they left it on (G1), and the footer reading "Enter · Paste into Slack" with the name of the app they came from (G8). They press Enter, or type two letters and then Enter: the flyout hides, the picture is in the composer, the message is not sent (G8, N3). Opened from the tray instead, the footer reads "Enter · Copy" and Enter copies (G8). Any tile drags out as a real file into any app that takes file drops, and `Ctrl+C` copies without hiding (G9).

Filling it: drop files, a folder or images from a browser onto the window (G11); `Ctrl+V` a copied image (G13); `Ctrl+O` to import files (G12); `Ctrl+PrtScn`, drag a rectangle, release: the screenshot is in the stash and on the clipboard (G14); `Ctrl+Shift+PrtScn`, drag, release, then Record: that region is recorded until Stop or the cap (G15); `Ctrl+Alt+V` stashes whatever image is on the clipboard without opening anything (G13). Each capture raises a small **notification** above the tray with the picture, its name and Undo, which never takes focus on its own, so the chat keeps the user's keystrokes (G16).

Tidying: the pin turns the flyout into a normal **pinned** window that stays open (G2). Items are renamed in place, tagged, favorited, multi-selected (G17) and deleted with Undo (G18). Tags are search words (G5); the chip row shows the ones carried by the most items (G4). Nothing requires a name or a tag (G17).

Editing: `Ctrl+E` opens the **editor** over the item inside the same window, with the tools Text, Crop, Trim, Hide and Draw (G20 to G23). Save renders the finished picture; the original is kept and every edit stays a layer that the next Edit brings back live (G26).

The most common failure: the destination does not take the paste, because the app cannot be sent input or its window is gone. ImageStash copies anyway and shows "Copied · press Ctrl+V" (G8). If the app also ignores the clipboard, the user drags the tile into the app's drop zone, or uses Save a copy… (G9) and the app's own attachment dialog. ImageStash reports what it put on the clipboard; it never claims delivery (G10).

## Non-goals

- **N1.** No folders, collections, albums or nesting of any kind, and no second "library" window. Tags, favorites, Recent and search are the whole organisation.
- **N2.** No accounts, cloud, sync, sharing, remote fetching, link unfurling, telemetry, crash reporting or automatic update. A drop, or a paste that would add to the stash, that carries only a link is refused, and nothing is downloaded; text pasted into the search box is searched, never fetched.
- **N3.** Nothing is ever sent. ImageStash never presses Send, never posts, and never inserts content except through the handoff (G8) the user triggered.
- **N4.** No video or audio. MP4, WebM, MOV and sound files are refused by name; recordings are silent GIFs.
- **N5.** No editing beyond the five tools and the options named in G20 to G27: no layers panel, zoom, bold or italic toggles, text alignment, opacity, layer reordering, duplicate layer, playback speed, reverse, loop count, per-frame editing, flip, straighten, filters, background removal, templates, sticker packs, or version history of edits. Anything else is an external editor's job: through Open with…, which changes the item in place (G27), or through Save a copy…, whose result comes back in as a new item.
- **N6.** No OCR, image recognition, automatic tagging, similarity search, fuzzy matching, or duplicate detection beyond exact byte equality.
- **N7.** ImageStash encodes no WebP. Recordings are GIF, and the finished picture of an edited WebP is a PNG for a still and a GIF for an animation.
- **N8.** No installer, Store listing, code signing, update channel, first-run tour, help page, plugin system, or language other than English. No macOS, Linux, Windows 10 or Arm builds; F13 says how the Windows code leaves room for a later macOS or Linux build, and nothing more is done for them.
- **N9.** ImageStash reads the clipboard only for the three explicit actions Paste image, `Ctrl+V` inside the window, and Stash clipboard image. No clipboard history or monitoring.
- **N10.** No multi-PC shared stash. ImageStash neither detects nor resolves conflicts a sync service creates. An export file carried to another PC and imported there (G36) is a copy taken once, not a shared stash.

## Operating envelope

Behavior outside these assumptions is not promised.

- **E1.** Each user runs one ImageStash instance at a time, in their own local interactive desktop session on a Windows 11 x64 PC whose Smart App Control is Off or in Evaluation, without administrator rights. Two Windows accounts on one PC are two users with two stashes (F6). Several displays with different scaling are admitted.
- **E2.** The stash is one folder on a local drive, at the default location or wherever Settings moved it, used by one running ImageStash on one PC at a time. A folder a sync service mirrors is admitted. No other program creates, edits or deletes files inside it while ImageStash runs; the conflict copies a sync service makes are outside the promise.
- **E3.** Admitted events: normal exit; a crash or kill at any moment; a cancelled capture; a failed or refused write; a sync service or antivirus scanner briefly holding a freshly written file open; a clipboard another program holds open; unsupported, undecodable or truncated input; a font missing from this PC; a global shortcut another program already holds; a destination app that cannot be sent input or transforms what it receives. Outside: power loss; disk failure; deletion or corruption of the stash folder by anything other than ImageStash; keystrokes another program suppresses before they reach a registered shortcut; another program writing to the clipboard in the instant after ImageStash's own write closes it.
- **E4.** The stash holds up to 5,000 items, each a file the PC can decode in memory. Beyond 5,000 items everything still works and speed is not promised; a file the PC cannot decode is refused (G35), and so is a file larger than the decoder L1 chooses for its format can read (for a JPEG, a side over 65,500; for a PNG, a side over 1,000,000). ImageStash imposes no other limit on an item, except that Save refuses (G35) a finished picture larger than its format can hold, or larger than the encoder L1 chooses for that format can write (for a JPEG, a side over 65,500; for a PNG, a side over 1,000,000).
- **E5.** Screen capture covers the visible content of the local displays. Content a program protects from capture, the secure desktop, and remote sessions are outside.
- **E6.** The app the user came from is an ordinary window that accepts keyboard input and reads the clipboard. Admitted: an elevated app, a window whose process ImageStash may not query (one run under another Windows account, for example), and a window that has gone, handled by G8's fallback; input the user gives to another window between ImageStash's activation of the target and its paste keystroke, which then goes to that window, or nowhere when Windows will not deliver it there; an app that ignores every clipboard format offered, where the user falls back to drag-out or Save a copy… as `In use` says. Outside: what any app does with the content after that.

## Fixed decisions

- **F1.** The product is named ImageStash. It is a Windows 11 x64 desktop application delivered as a self-contained build the user copies onto a PC and runs; it registers itself to start with Windows while that setting is on.
- **F2.** It is written in C# on .NET 10 with Avalonia UI.
- **F3.** Supported formats: PNG and JPEG (`.jpg`, `.jpeg`), still; GIF and WebP, still or animated. An animated PNG is handled as a still. An imported file is stored as the file it came as; nothing is converted on import. Screenshots and stashed clipboard images are PNG. Recordings are GIF at a fixed rate of 15 frames per second, or the nearest rate GIF timing allows. An edited item's finished picture is in its original's format, except WebP: PNG for a still, GIF for an animation.
- **F4.** There is one stash window, with two states, flyout and pinned; the preview and the editor are overlays inside it. Notifications are ImageStash's own small windows above the tray. Settings is one separate page. The capture overlay, the recording frame and its bar exist only during a capture, and a standard Windows dialog (file picker, Open with) only while open. There are no other windows.
- **F5.** Default global shortcuts, each remappable in Settings: `Ctrl+Alt+Space` opens or hides the stash window; `Ctrl+PrtScn` takes a screenshot; `Ctrl+Shift+PrtScn` starts and stops a recording; `Ctrl+Alt+V` stashes the clipboard image.
- **F6.** The stash is one plain folder. Every item's finished picture is an ordinary file in it; the original of an edited item is kept in a subfolder beside it; one metadata store in the folder holds names, tags, favorites, use history and layers. The default location is `%LOCALAPPDATA%\ImageStash\stash`, which gives each Windows user account its own stash. The app's settings (shortcuts, options, window sizes and positions, the stash location) live under `%LOCALAPPDATA%\ImageStash`, outside the stash folder.
- **F7.** An item is its original file, which ImageStash never modifies; its ordered list of layers; and its finished picture. An item without layers has one file, which is both. Layer kinds: text and caption bar (both made with the Text tool), hide, draw mark (pen, marker, arrow or box), crop, trim and shrink. A text layer carries its preset, text, font, size, fill color, outline color, position, rotation and, on an animated item, a time range; a caption bar carries text, font, size, fill color and outline color only.
- **F8.** The Text tool's font menu lists, in this order, Impact, Arial Black, Segoe UI, Comic Sans MS, Georgia, Consolas, Bahnschrift, Segoe Script, Ink Free and Verdana, then the selected layer's font when it is none of these, then All fonts…, which lists every font installed on the PC and stays open while fonts are chosen from it; the menu marks the selected layer's font, and so does the list when that font is installed. The Meme preset defaults to Impact; the other presets default to Segoe UI.
- **F9.** An item has a name, optional tags, a favorite flag and a use history, and nothing else to file it under.
- **F10.** The look is Windows 11's: Fluent styling, Segoe UI text (the Text tool's font menu and All fonts… show each font's name in its own face, a variable font's instances in that font's default face, a symbol font's name in the look's own text), Segoe Fluent Icons, the system accent color, light or dark by the system setting or the Settings choice. All text is English.
- **F11.** The metadata store carries a version number, and every later build reads stores written by earlier builds.
- **F12.** Auto names are `Screenshot YYYY-MM-DD HH.MM.SS` and `Recording YYYY-MM-DD HH.MM.SS` in local time; a stashed clipboard image is named like a screenshot; an imported file carries its file name without its extension.
- **F13.** Windows is the only platform built, and nothing is promised on any other. The code is arranged so that a later Linux or macOS build adds platform parts without rewriting the rest: everything that reaches Windows itself (the tray and its menu, global shortcuts and the keyboard-layout check, screen and pointer capture, the clipboard, the caret, the paste target and the paste keystroke, keeping notifications from taking focus, a window's rounded corners, a border drag held at the window's minimum, the Recycle Bin, Start with Windows, the installed fonts, the file and Open-with dialogs, Reveal in File Explorer, and the default file locations) sits behind seams the technical specification names, and the stash, search, metadata, editor, rendering and encoding reach Windows only through those seams. No code for another platform is written, and no Windows behavior in this document is weakened for the sake of a seam.

## Guarantees

**Summon and window**

- **G1.** The open shortcut and a left-click on the tray icon show the stash window within one second of the press, while other programs are not saturating the PC, no other program holds the metadata store or its journal open (E3), ImageStash is not still opening the stash at its start, finishing what a crash, a kill or a failure left unfinished (G28) or checking the Open with… copies it watches (G27), and ImageStash is not rendering again a finished picture whose Save, or whose restoring by an Open with… Undo, was left unfinished by a refused write or a file held past its retries (G35). It shows with the search box focused and its text selected, so that typing replaces it, and with the scope, search and selection it was left with, as one continuing session; at the first show after start, Recent (or All while Recent is empty) with its first item selected. From the shortcut, the flyout opens beside the text caret of the focused control in the app the user came from, over the caret when neither side of it has room for the window's minimum width; when no caret can be found, at the mouse pointer; else centred on the active display; always fully on screen. From the tray or a notification it opens above the tray icon. While pinned, the window comes forward where it is. When the window already holds an open edit or preview, summoning brings it forward as it was left.
- **G2.** The flyout and the pinned window show the same content and answer the same keys. The flyout hides on losing focus to another app, after Enter's paste, on the open shortcut, and on Esc once there is nothing else to close (Esc closes the preview, else clears the search, else hides; pinned, it goes no further). It stays while a drag it started is in progress, while a dialog it opened is up, and while an edit is open; during an edit the open shortcut brings it forward instead of hiding it. Pinning gives it a title bar, resizing, a taskbar button and persistence; Close unpins and hides it, and the shortcut then brings it forward. Flyout size, and pinned size and position, are remembered separately. On first run with an empty stash the window opens pinned, and the empty stash lists every way in with its shortcut and accepts drops.
- **G3.** Starting a screenshot hides the flyout, or minimises the pinned window, until the capture ends, and puts back only what it hid or minimised: a window that was hidden or minimised already stays so, and a flyout with a dialog it opened up or a drag it started in progress stays, as G2 says. Starting a recording hides or minimises it the same way, and while the region waits to be recorded or the recording runs the open shortcut summons it again as usual. An open edit is kept through either and is there when the window shows again. Closing the window never exits ImageStash; Quit in the tray menu does. Launching ImageStash while it already runs for this user opens the running instance's window as a left-click on its tray icon would, and starts nothing else.

**Finding**

- **G4.** Recent lists items by their latest use (G10), newest first; All, Favorites and search results list newest-added first. The tag chips after the scopes are the tags carried by the most items; when the row cannot hold every tag, a chip at the row's right edge, which stays put as the other chips come and go, lists every existing tag, the commonest first, scrolling when long. Clicking a chip adds its tag to the search as a word, in place of a typed word the tag contains, so several chips and typed words narrow the grid together; clicking a lit chip removes its word from the search; clicking Recent, Favorites or All clears the search and shows that scope.
- **G5.** Typing searches names and tags across the whole stash, case-insensitively: the query is split on spaces, every word must be a substring of the name or of one tag, and a leading `#` is ignored. While a query is typed, the All chip is lit, the grid shows the matches (ordered as G4 says), the selection moves to the first match, and Up and Down move it while the search box keeps focus. The chip row then shows, in this order: the tags that are words of the query; the tags that contain a word of the query without being one, so a tag being typed stays in reach; and the tags that would narrow the matches further (carried by some of the matches, not by all), the most carried first. A chip is lit while its tag is one of the query's words. The no-match state names the query and offers Clear, and is distinct from the empty stash. Clearing the search returns to the scope the user was in.
- **G6.** Thumbnails sit in justified rows at their real aspect ratio (ratios outside 0.62 to 2.1 are cropped in the grid only). An animated item plays only while hovered or selected, and only one plays at a time. An animated item carries a `GIF` or `WEBP` badge naming the file it is handed over as; a still carries no badge. Transparency shows on a neutral tile in the grid and on a checkerboard in the preview and the editor. `Ctrl`+wheel and `Ctrl` with `+` or `-` step the thumbnail size through three sizes, remembered. A tile, the preview and a capture notification show the picture their item's file held when the stash was last listed; when a rename lands under a read of that file still in progress (one retrying a file another program holds, E3, included), they may show the picture the rename put at that path until that reader next reads the file, no later than the item's next change of picture, the next thumbnail size, or the next opening of the preview or the notification.
- **G7.** The search box is an ordinary text box: it takes every typed character, including Space, Backspace and Del, and Left, Right, Home, End, Shift with them, `Ctrl+A`, `Ctrl+X` and `Ctrl+Z` edit its text and selection as in any Windows text box, never the grid. Up and Down move the grid selection from either place without moving focus; Left and Right move it from the grid. Tab, or a click on the grid (on a tile, or on the blank space between or around the tiles, which leaves the selection as it is), moves focus to the grid, where Space, Del, F2, `Ctrl+D`, `Ctrl+E` and `Ctrl+A` act on the selection and typing returns focus to the box. Enter, `Ctrl+V`, `Ctrl+O` and Esc work from both; `Ctrl+C`, from both, copies the box's selected text while it has one and otherwise the selected items. The whole paste path (summon, search, select, preview, handoff) works with the keyboard alone and with the pointer alone, with visible focus.

**Handoff**

- **G8.** Enter, a double-click, and the first item of an item's menu perform the **handoff** on the selection. The handoff puts the finished picture of each selected item on the clipboard as a file, and for a single still also as a bitmap that keeps its transparency; animated items and multi-selections go as files only. When a **paste target** is known, ImageStash hides the flyout, activates that window and sends it a paste keystroke, and the footer and the menu name the target by its app name. When there is none, Enter copies and the footer reads Copy. When the target is gone, or is a window ImageStash cannot send input to (an elevated app, or one whose process it may not query, E6), ImageStash copies and raises a notification reading "Copied · press Ctrl+V". When the clipboard cannot be written, nothing is pasted and the failure is named (G35). While another program holds the metadata store open (E3), the handoff and `Ctrl+C` hand over an item the window has listed since the stash last changed, and refuse by name (G35) one listed before that, until the store can be read again. From the moment Move…, Export stash… or Import stash… begins copying until it ends, the handoff, `Ctrl+C` and a drag-out are refused by name (G35). The paste target is set when the open shortcut is pressed while another app is in front, to that app's window, and whenever ImageStash gains focus any other way, to the window that had focus just before, passing over the shell's task switcher; it is none when that window was ImageStash itself, one of its notifications, the desktop or the taskbar; while ImageStash has not yet heard from Windows which window had focus just before it, it is none until it hears, and then that window. The stash window shown again at the end of a capture (G3) keeps the paste target it had.
- **G9.** `Ctrl+C` copies the handoff's clipboard content (G8) and the window stays. Dragging tiles out of the window is a file drop of their finished pictures, while no change of those items has run or is in flight since the window last listed them, and the flyout stays until the drop lands. Save a copy… writes the finished picture to a path the user chooses outside the stash folder (a path inside it is refused, G35) and does not overwrite an existing file without confirmation. Reveal in File Explorer acts on the finished picture's file, and Open with… on a copy of it (G27).
- **G10.** A **use** is a handoff, a `Ctrl+C` copy or a drag-out. Each one that completes records one use, with its time, on each item involved, and that is all it records; one that fails records nothing. A use the store refuses to record is named as a failure (G35), and the handoff, copy or drag-out it belongs to stands. Nothing in ImageStash states or implies that content was delivered.

**Collecting**

- **G11.** A drop onto the window accepts files, a folder (its supported files, not recursively), and images dragged from browsers or chats as files. Before release the drop card says how many files are supported and how many will be skipped as unsupported, judged by their names; whether a supported file is a duplicate or unreadable is known only after release (G12). The stash always makes copies; sources stay untouched. While a tag chip is lit, new items get that tag.
- **G12.** An import (a drop, or `Ctrl+O` and the Import files… dialog) adds one item per supported file, named after its file (F12). A file whose bytes equal an existing item's original is not added again and is reported as already in the stash. An unsupported file is skipped and named with its type and the four supported formats. A notice inside the window states the result for every file, with Undo, which removes everything that batch added. After an import the search is cleared and the window shows All with the new items first and selected.
- **G13.** Paste image and `Ctrl+V` in the window import the files on the clipboard as a drop would (G12), or, when it holds no files, save the clipboard's image as a PNG item; when it holds neither, `Ctrl+V` in the search box or in a tag field pastes the clipboard's text into that field (in the tag field as typed text, so Enter then adds its words as tags), and otherwise a notice says so and nothing is added. Stash clipboard image (`Ctrl+Alt+V` anywhere, or the tray menu) saves the clipboard's image as a PNG item without opening a window and raises the capture notification (G16); files on the clipboard do not count, and when there is no image a notification says so and nothing is added. A pasted image is always a still, and the result says that an animated image is added by dragging its file in.
- **G14.** The screenshot shortcut freezes and dims every display. A drag selects a rectangle within the display it started on, with a size label; release saves those pixels as a PNG item with the auto name (F12), copies it to the clipboard while "Also copy" is on, and raises the capture notification (G16); nothing else is asked. Esc, or a click without a drag, cancels.
- **G15.** The record shortcut opens the same overlay (G14); release lifts the dimming, so the screen stays live and clickable, and the region waits to be recorded: it keeps a thin red frame and a bar beneath it (above it when there is no room below, over its bottom edge when there is room on neither side) offering Record and Cancel, so what is about to be recorded can be set up first. Record, or the shortcut again, starts recording: the frame carries a REC label, the bar shows elapsed time against the cap, the size so far, Stop and Cancel, the tray icon shows a red dot, and the tray menu's Record a clip reads Stop recording (G34). Recording ends on Stop, on the shortcut, or at the cap; Esc ends neither the wait nor the recording, because the app being recorded may need it; Cancel, while the region waits or while it records, discards it. When the PC cannot sample and encode the region at F3's rate, samples are skipped and each kept frame lasts until the next, so the clip still lasts the recorded time at a lower rate. The clip is written as a GIF item with the auto name (F12) without further input, copied while "Also copy" is on, and announced by the capture notification (G16) once the file is saved. The pointer is recorded unless Settings says otherwise; the frame, the bar and the notifications are never recorded; any other window inside the region, ImageStash's included, is.
- **G16.** The capture notification shows the picture (for a recording, with its length and size), says it is in the stash (and on the clipboard when it is), shows the name as a field whose text is selected so that typing replaces it and Enter confirms, and offers Edit (Trim for a recording) and Undo. Undo removes the capture; if that item is open in the editor, the editor closes without saving. Edit opens the stash window on that item in the editor, pinned if the window was pinned and otherwise as a flyout above the tray; Trim does the same with the Trim tool selected; a click anywhere else on the notification, outside its field, buttons and ×, opens the stash window the same way with that item selected and no editor, and dismisses the notification. Notifications appear above the tray on the primary display, stay six seconds and longer while hovered or while their field has focus, never take focus on their own, and each carries a × that dismisses it. A notice inside the window lasts the same six seconds, longer while hovered, whether or not the window is visible, carries the same ×, and its Undo acts while it shows.

**Organising**

- **G17.** Rename (F2, clicking the name in the preview, or the capture notification's name field) edits in place; when the item is what ImageStash last put on the clipboard, the clipboard follows the renamed file as it does after a Save (G26). `Ctrl+D` toggles favorite, and a mixed selection becomes all favorites. `Ctrl`-click, `Shift`-click and `Ctrl+A` multi-select. Add tag ▸ lists Type a tag… first, then every existing tag, the commonest first, marking each tag every selected item carries; a click on a listed tag adds it to every selected item, or removes it from all of them when all carry it, and the list stays open for the next. Remove tag ▸ lists the tags the selection carries; a click removes that tag from the selection and leaves the list open. A list longer than fits scrolls. Dragging tiles onto a tag chip or onto Favorites applies it. The tag field adds the words typed or pasted into it as tags on Enter, with suggestions from existing tags, suggesting only tags the item does not yet carry; while nothing is typed, one click offers every existing tag to pick from, listed and marked as Add tag ▸ lists them, a pick adding or removing the tag as a click there does, and the field's own tags follow at once; tags are removed with their ×; it stays open after each tag it adds, so several are added in a row, and closes on Esc (an open list of every tag closing first, on its own Esc) or when focus leaves it. A tag no item carries ceases to exist. Nothing ever requires a name or a tag.
- **G18.** Delete (Del, or the menu) moves the item's files, finished picture and original, to the Recycle Bin and removes the item at once, without a dialog; a notice with Undo restores all of it while the notice shows. Several selected items delete together the same way.
- **G19.** The preview (Space, `Ctrl`+double-click, or the menu) shows the item at full size, scaled down only when the window cannot hold it and never enlarged, with its animation playing (a click pauses), its type, dimensions, file size and duration, when it was added, how often and how recently it was used, "Edited here" with its layer kinds when it has layers, its tags, the handoff button named as in the footer (G8), Copy, Edit, and a ⋯ menu with Rename, Save a copy…, Open with…, Reveal in File Explorer, Delete, and on an edited item Revert to original and Save as new item. Inside the name or tag field Enter commits and Esc cancels that edit.

**Editor**

- **G20.** Edit (`Ctrl+E`, the preview's Edit, a menu, or a notification's Edit or Trim) opens the editor over one item inside the window. `Ctrl+E`, the menus' Edit and the preview's Edit act on the one selected item and are unavailable with several selected; a notification's Edit acts on its own item; opening the editor on another item while an edit is open first leaves that edit as Cancel would. While a change of that item is running or waiting to run, or runs while Edit's open is still reading the original (retrying a file another program holds, G35), Edit opens once that change has run, or is refused by name (G35) when the change moved the file Edit was reading, and opens when asked again. The editor shows the original with the item's layers live and selectable; the tools Text, Crop, Trim (animated items only), Hide and Draw; an option row for the current tool that states what the mouse does; Compare, which shows the original while held; a ⋯ menu with Save as new item, Revert to original (on an edited item) and Discard changes; Cancel; the output size; and Save, every one of them inside the window on a display whose working area holds the window's minimum size (L2). While the editor is open Enter never pastes. Cancel, the back arrow, and Esc with nothing selected leave the item as it was and put up a notice with Undo that brings the discarded edit back.
- **G21.** Text: a click adds a layer of the current preset (a text layer, or for Caption bar a caption bar), a double-click edits it, a corner handle resizes it, and on a text layer a drag moves it and a round handle above the box rotates it, snapping to 15° steps while Shift is held and resetting on double-click. Meme is uppercase with an automatic outline, placed at the top or bottom; Caption bar is a white bar above the picture with black text, which extends the picture's height; Label is plain text anywhere. With a text or caption-bar layer selected, the option row shows the presets, the font menu (F8), five fill swatches plus a More swatch that opens the color picker, and an outline swatch; with none selected, the presets and "Click the picture to add text"; when the window is too narrow for the row, the row wraps and, on a display whose working area holds the window's minimum size (L2), nothing is clipped or hidden. The fill and outline colors are the text's; a Caption bar's bar is always white. The color picker offers any color, an eyedropper that samples the picture, and the colors used recently; opened from the outline swatch it also offers Auto (black on a light fill, white on a dark one) and None. Meme and Label default to Auto, Caption bar to None. The Windows emoji panel (`Win+.`) inserts into the layer. A layer whose font is not installed renders in a fallback and the editor says so. Font, colors and rotation render into the finished picture as shown.
- **G22.** Crop: corner handles and dragging the picture, a 1:1 option, and Reset; the whole original is kept, so a crop can be widened later. Trim: a filmstrip of every frame under the picture with two handles, a playhead, play and pause, the kept range and its length, and Reset; frames outside the handles stay in the original. On an animated item a text, hide or draw layer has a start and an end, the whole clip by default, shown as a bar over the filmstrip whose ends drag, and a trim moved later does not move them; a caption bar spans the whole clip.
- **G23.** Hide: a dragged rectangle becomes a layer that blurs, or with Black box fully covers, what is under it, and can be moved or resized later. Blur is cosmetic; Black box leaves nothing of what it covers in the finished picture, while the original underneath stays in the stash folder. Draw: Pen, Marker (a translucent wide stroke), Arrow (a line with a head at its end) and Box (an outlined rectangle), in the five swatch colors or any picked color, at three thicknesses. Each mark is its own layer: a click selects the mark under it, a drag that starts on the selected mark moves it, any other drag draws a new mark, and Del removes the selected one.
- **G24.** The editor's footer states the finished picture's dimensions and estimated file size for the current layers. The Shrink choice behind it (full, three-quarter or half size) is a layer and applies at Save. The preview and the capture notification show the measured size of the saved file.
- **G25.** In the editor, `Ctrl+Z` and `Ctrl+Y` undo and redo within the session; `Ctrl+S` saves; Del removes the selected layer; inside a text or caption-bar layer's text, Del deletes a character, Enter adds a line and `Ctrl+Enter` leaves it; Space plays or pauses; Left and Right step one frame; C holds Compare. Undo within an edit does not survive leaving the editor; after Save, the layers are the only history.
- **G26.** Save renders the finished picture in F3's format, keeps every layer live for the next Edit, returns to where Edit was started (the preview or the grid; a window a notification opened stays open with the item selected), and replaces the clipboard when nothing has changed it since ImageStash put this item there. Save as new item makes a second item from a copy of the original, the current layers and the same tags, not favorite, named with a counter ("the audacity 2"), leaves the item being edited as it was, and continues editing the new one. Revert to original removes every layer: from a menu, at once with a notice and Undo; inside the editor, at Save. The grid shows no edit marker.
- **G27.** Open with… opens the Windows Open-with dialog on a copy of the finished picture that ImageStash keeps for the item outside the stash folder. Asked again on an item whose copy no program has rewritten, it replaces that copy with a fresh one, and a rewrite landing in the instant of that replacement is removed with the old copy and not adopted. When a program other than ImageStash rewrites that copy with different bytes and the result can be decoded, the rewritten copy becomes the item's new original and finished picture, any layers it carried are dropped, the thumbnail refreshes the next time the item is shown, and a notification above the tray says so with Undo when the adoption's file steps complete at once; an adoption a refused write or a held file stopped after its commit (E3) is named as a failure then (G35) and, when a later change of the item or the next start finishes it, completes without the notification, its previous original going to the Recycle Bin no later than the next start. Undo restores the previous original and layers and moves the outside version to the Recycle Bin; after a Save or Revert of the item, Undo is refused by name, since the layers are then the only history (G25), and after a later adoption into the item an earlier notification's Undo is refused by name, the latest one's stepping back one version and the earlier adoption's previous original going to the Recycle Bin at that later adoption; once the notification has gone, or its Undo was refused, the previous original goes to the Recycle Bin instead. A rewritten copy that cannot be decoded is not adopted: the item keeps its previous original and the failure is named (G35).

**Durability**

- **G28.** After a crash or kill at any moment, every item saved before it, with its original, finished picture, name, tags, favorite flag, use history and layers, is intact when ImageStash reopens; the change in flight is absent or complete, never partial, except that one whose finishing and undoing both need a write still refused at that start (E3) stays pending, named as a failure, until a later start finishes or undoes it, every other item opening (G35). No success is shown before the write it reports has completed.
- **G29.** Nothing in ImageStash modifies an original's pixels or an imported source file. A rendered finished picture is replaced by the next Save, Revert to original or Open with… adoption and is not kept; an original is never removed that way (an unedited item's single file becomes the original of the edited item, F6). Otherwise files are removed from the stash only through Delete, Move, Import stash… (G36), and the Undo or expiry of a notice or notification (a removed capture or import batch, an Open with… replacement, whose expiry a later adoption of the same item or the next start brings forward, G27). All but Move send the files to the Recycle Bin, which keeps what it is sent only up to the size Windows allows it for that drive and removes anything larger for good, and everything for good while the bin is turned off for that drive; a removal for good completes the Delete, Undo or expiry that asked for it.
- **G30.** Move… copies every file and the metadata to a chosen empty folder, switches to it, then removes the old copy; if the copy fails partway, nothing changes and the failure is reported.
- **G31.** Replacing the executable with a newer build keeps every item, its layers and every setting usable.

**Settings, shortcuts and tray**

- **G32.** Settings is one page, opened from the tray menu and from a Settings button beside the stash window's + button, and brought forward, not opened twice, when asked for while it is open. It holds: the four shortcuts as press-to-record fields; Also copy a capture to the clipboard (on by default); the recording's maximum length from a short list (30 seconds by default) and whether the pointer is recorded (on by default); the stash location with Open folder and Move…; Export stash… and Import stash… (G36); Start with Windows (on by default); Theme (system, light, dark). A shortcut field reads a press as its key with the modifiers held when the key went down, for a key pressed while the field records and with no modifier pressed while it is held, and PrtScn, whose press Windows withholds, with the modifiers held from the last modifier's press until it comes up; Esc alone ends the recording and Tab, with or without Shift, moves on, none of them read as a press. It refuses, with a warning on the spot, a combination another program holds, one that types a character on the current keyboard layout, `Ctrl+V`, the paste keystroke the handoff sends (G8), or the combination one of the other three shortcuts uses.
- **G33.** A shortcut that cannot be registered, or that would type a character on the keyboard layout in use, checked at start, at each registration, at least once a second, and before a shortcut acts, is left unregistered until it is changed in Settings and leaves every other function working: the tray icon says which shortcut is unavailable and why, the why giving way only when the tooltip cannot hold it beside every other failure named there; Settings opens on that row; the tray menu and the window still reach every action. Pause shortcuts in the tray menu releases all four until toggled back.
- **G34.** The tray menu holds Open ImageStash, Take a screenshot, Record a clip (Start recording while a region waits to be recorded, Stop recording while recording), Stash clipboard image, Pause shortcuts, Settings and Quit ImageStash, each with its shortcut shown. A left-click on the icon opens the stash window; a right-click opens the menu.
- **G36.** Export stash… writes the whole stash (every item's original and finished picture, and the metadata store with every name, tag, favorite flag, use history and layer list) together with the settings that are not about this PC (the four shortcuts, Also copy, the recording's maximum length and whether the pointer is recorded, Start with Windows and Theme; not the stash location, the thumbnail size or the windows' sizes and positions) into one file at a path the user chooses outside the stash folder, showing a busy state naming it while it writes and saying where the file is once it is written; nothing in the stash changes. Import stash… opens such a file, says how many items it holds and that the current stash and those settings will be replaced by it, and, once the user confirms, replaces them at the current stash location, the replaced stash's files going to the Recycle Bin (G29); the imported items are then found, edited and handed over as they were on the PC that exported them, and the imported settings take effect at once. Import is a replacement, not a merge: an item the current stash held and the file does not is gone from the stash with the rest of it. Both wait, as Move does, while a capture, a recording, an edit or another change is in progress, and from the moment one is asked nothing else starts until it ends, but a handoff, a `Ctrl+C` copy or a drag-out before its copy begins (G8). A file that is not an ImageStash export, or one written by a newer build whose store this build cannot read, is refused by name (G35) and nothing changes. An export that fails partway or is killed, and an import that fails or is killed before its record is written, leave the current stash and settings as they were; after the record, a failure or a kill leaves the import finished whole at the next start, or, while a write it needs is still refused there, at the first later start at which it succeeds, the window showing the import's failure meanwhile (G30's rule, G28).

**Errors**

- **G35.** Every refusal names what was refused and why ("clip.mp4 is a video"). Every failure names the action that failed and leaves unrelated items usable. A busy state identifies its action and never presents unfinished work as done. A file a sync service or antivirus scanner briefly holds open is retried before its failure is named (L2 sets for how long). An undecodable or truncated file is refused as unreadable and never crashes ImageStash. A JPEG whose scan data stops at a marker before its picture is complete is the one exception: it is read as the picture its decoder still makes of it, which may show noise, grey or lost detail where the data is missing.

## Left open

- **L1.** The technical writer chooses the layout of files and the metadata store inside the stash folder, the decoding and encoding libraries, the capture and recording mechanism, how the caret and the paste target are found, how the paste keystroke is delivered, which clipboard formats carry G8's bitmap, the GIF palette and size-estimate method, how notifications are kept from taking focus, and the seams F13 requires, under F3, F6, F11, F13, G8, G15, G16 and G28. Nothing is scaffolded for sync or for capabilities outside this document, and no code for another platform is written.
- **L2.** The implementer chooses pixel layouts and the look's colours, edges and corner radii, the stash window's minimum size (the smallest at which the editor's rows fit whole, the option row wrapped), the three thumbnail sizes, the three thickness values, the marker's translucency, how many recent colors are kept, the recording length list, how often the size estimate refreshes, how long a held file is retried (G35), and the wording of messages not quoted here, as long as every line of this document holds.
- **L3.** Nothing is pending with the user.
